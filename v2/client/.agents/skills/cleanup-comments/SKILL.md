# Cleanup Comments

Only edit comments. If a fix needs a code change, tell the user instead.

## Delete

- Comments that restate the code (`// increment i`)
- Narration of edits ("removed X", "updated to use Y", "new approach")
- Stub markers and filler ("implementation here", "generated by AI")
- Section banners and decorative separators
- Docstrings on private or obvious functions

## Keep

- The why: workarounds, hardware quirks, protocol details, units, timing
- Invariants, gotchas, links to specs or issues
- Real TODOs
- Docstrings on public APIs

## Style for what stays

Short, plain, lowercase is fine. No "This function...", no emojis, no em dashes.

## Process

1. Work on files changed vs the default branch unless told otherwise
2. Show a summary: comments removed, comments kept
3. Never touch code, strings, or formatting
