# Changes to the main Vizibble application

Everything below exists to support Vera, and all of it is inert until `AI_INTEGRATIONS_ENABLED=true`. No existing endpoint changed its contract, and telemetry ingestion is untouched. Nothing in `server`, `client` or `shared` imports Vera.

## Backend (`server/`)

| Change                                                                                                                                     | Why                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `better-auth` and `@better-auth/drizzle-adapter` 1.7.9 → 1.7.20 (patch)                                                                    | Required by `@better-auth/oauth-provider`                                                                                                                                                                                                                                                                                                                            |
| `jwt` + `oauthProvider` Better Auth plugins ([lib/auth.ts](../../server/src/lib/auth.ts))                                                  | Makes the main app the OAuth 2.1 authorization server for ChatGPT/Claude: dynamic client registration, PKCE, consent, refresh-token rotation, revocation, JWKS. Scopes: `vizibble:read`, `vizibble:write`. 15-minute access tokens. Clients can only be created through registration (`clientPrivileges` denies everything else)                                     |
| OAuth route gating and RFC 8414 metadata ([app.ts](../../server/src/app.ts))                                                               | OAuth endpoints return 404 when AI integrations are disabled. When enabled, metadata is served at `/.well-known/oauth-authorization-server/api/v2/auth` and token/registration endpoints allow cross-origin calls                                                                                                                                                    |
| Migration `0009_ai_integrations`                                                                                                           | Better Auth's tables (generated with `bunx auth generate`), plus `integration_link_codes` and `integration_grants` (only hashes of codes and tokens are stored)                                                                                                                                                                                                      |
| Integration API `/api/v2/integrations/v1/*` ([routes/integrations.routes.ts](../../server/src/routes/integrations.routes.ts))              | Vera's only door to business data. It needs Vera's service token **and** a user delegation the server verifies: a live OAuth consent (MCP) or a live WhatsApp grant. It then runs the dashboard's own `requireOrganisationMember` + `requirePermission` and reuses the existing controllers. Writes also need a write-enabled delegation (`requireIntegrationWrite`) |
| New reads: `GET /me`, `GET /organisations/:id`, scoped device list with connectivity, keyset-paginated raw readings (accepts `time_range`) | The existing APIs had no identity summary, no location-scoped device list and no cursor pagination                                                                                                                                                                                                                                                                   |
| WhatsApp linking: `POST /integrations/v1/whatsapp/link` (service only) and `DELETE /integrations/v1/whatsapp/grant`                        | Exchanges a single-use code for a grant. Relinking a number revokes its previous grant                                                                                                                                                                                                                                                                               |
| User-facing `/api/v2/integrations` (session)                                                                                               | Overview of connections, create a link code (10 minutes, single use, membership checked), unlink WhatsApp, disconnect an AI app (consent deleted through Better Auth, tokens revoked)                                                                                                                                                                                |
| Env: `AI_INTEGRATIONS_ENABLED`, `VERA_MCP_URL`, `VERA_SERVICE_TOKEN`, `VERA_WHATSAPP_NUMBER` ([lib/env.ts](../../server/src/lib/env.ts))   | Off by default. When enabled, the URL and a token of at least 32 characters are required                                                                                                                                                                                                                                                                             |

## Frontend (`client/`)

| Change                                     | Why                                                                                                                                                                                                                        |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Integrations** page (utility navigation) | Connector address and setup steps for ChatGPT/Claude, connected apps (read-only or can make changes) with Disconnect, WhatsApp linking (code, wa.me link, countdown, auto-refresh when linked), linked numbers with Unlink |
| `/oauth/consent` page                      | Better Auth's consent step: shows the app and what it may do. **Changing data is an unticked opt-in** even when the app requests it                                                                                        |
| Login continues OAuth flows                | With `oauthProviderClient`, signing in during a ChatGPT/Claude connection resumes that flow instead of opening the dashboard                                                                                               |

## Shared (`shared/`)

`integrations.ts` (Zod contracts) and new paths in `routes.ts` for both APIs.

## Infrastructure

- The main Dockerfiles copy `Vera/package.json` (manifest only) so the frozen workspace lockfile resolves. Vera's code never enters the main images.
- `infra/docker-compose.yml` and `infra/.env.example` gain the four AI variables (default off).
- Caddy forwards `/.well-known/oauth-authorization-server*` and `/.well-known/openid-configuration*` to the API.
- The root `package.json` adds Vera to the workspaces and pins `jose` (`overrides`) so Better Auth packages share one copy.
